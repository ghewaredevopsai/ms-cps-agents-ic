Course Overview

What this day does

  • Takes the IC team from Copilot user to agent builder — agents that sit inside workflows, not beside them
  • Answers the two questions you raised directly: how Copilot Studio calls an API, and how the agent deploys into an existing system
  • Every example is an investment-consulting one — asset owners, pension funds, fund research, client reporting
  • Converges on one flagship agent that replaces your manual unstructured → structured → PowerPoint pipeline

What this day deliberately excludes

  • No licensing theory — no SKU/entitlement sessions
  • No AI history for its own sake — one orientation slide places Copilot Studio on the ML → deep learning → generative → RAG → agentic path, and that is all
  • No hype — model behaviour is covered only where it changes what you build
  • No non-Microsoft tooling — nothing you cannot run under current governance
  • Microsoft Agent Framework / code-first frameworks are positioned as the graduation path, not built here
The ROI test for the day. Participants must leave able to build an AI agent integrated into a workflow — not merely better at prompt engineering. Every session below is scored against that single criterion, and the capstone is the proof.

Learning Outcomes

Understand

  • How the model actually behaves — and where it will fail on consulting work
  • What an "agent" really is in Copilot Studio: instructions, knowledge, topics, actions
  • Where Copilot stops and an agent begins — and why the pilot has not moved the needle
  • Copilot Studio's real limits on scale and control, stated honestly

Build

  • Agents that call external and internal / legacy REST APIs
  • Data movement through Excel and SQL, in and out
  • Unstructured → structured extraction from fund documents
  • PowerPoint report generation without the manual Aspose step

Deploy & Govern

  • Publish and deploy the agent to Teams; share it with a team
  • Link an agent into an existing enterprise workflow
  • Work a governance checklist: DLP, data boundary, connector approval, audit
  • Know when to stay in Copilot Studio and when to graduate to code-first

1.1 What an "Agent" Really Is in Copilot Studio Core ~30 min

  • Where Copilot ends, Copilot Studio begins and Microsoft Foundry starts — three products on one spectrum, and the two questions that settle which one you need
  • Agent anatomy: instructions, knowledge, topics, actions, orchestration
  • What actually starts an agent — a person, a file landing in a library, a schedule, an email, or another agent — which is what puts the work inside the process rather than beside it
  • How the agent decides what to do at runtime — and why the trace is the first place you look when it chooses wrongly
  • Six agents teams actually build — what starts each one, what it touches, what it returns, and which is the realistic first
Built at the end of the morning — these four slides describe the agent; it is built live once the prompting work is done, so the room sees what a prompt is worth before it sees what an agent adds.

1.2 Prompting for Consulting Work — and Why Answers Drift ~70 min

  • Structured prompts: role, context, task, output format, examples
  • Why each part earns its place — the specific failure that comes back when you drop it
  • Four worked prompts, one per consulting job — manager update → house question list, meeting notes → decisions and owners, holdings → data-quality check, draft commentary → house tone — each built from the same five parts and run on screen
  • Why figures get invented — fabrication, the right number for the wrong thing, stale data — and exactly what grounding fixes and what it leaves to you
  • Turning a prompt that works into a team asset rather than a chat message
Live demo — a reusable prompt pack for asset-owner reporting: fund summary, manager commentary, data-quality check; then one fund question through three prompts, on screen: watch the answer drift, then watch grounding fix it. Participants are welcome to follow along on their own machines.

1.3 Where It Fits Your Workflow — and Which Agent to Build First Key ~35 min

  • Honest limits: scale, control, latency, and what that means for production use
  • Mapping the IC workflow: research → analysis → report → client
  • Why the Copilot pilot has not produced gains — assistance vs integration
  • Positioning the internal GPT tool: what it does, what an agent adds
  • Picking the first agent: value, risk, data readiness, repetition volume — and why the least glamorous candidate is usually the right one
Live demo — your reporting pipeline drawn on screen and marked step by step (prompt-only, agent-suitable, human-only), then the four criteria applied to pick the first agent actually worth building.

Live Build — Your First Agent, End to End Core ~35 min

  • First the three-click version anyone can build over a document library — so the non-developer majority leaves with something they can do unaided
  • Then a Fund Research Assistant built from empty in Copilot Studio: grounded on sample fund factsheets, tested and corrected on screen
  • The reusable prompt from 1.2 becomes the agent’s Instructions — the same words, now permanent, shared and callable
  • Deleting one line from those Instructions, to show what the refusal rule was holding back
Live demo — the morning closes on a working agent, and the afternoon extends that same agent rather than starting again.
View slides → Module 2 — Hands-on Agent Building  ·  ~5 hrs  ·  all 35 present · build depth pitched at the ~10 developers Goal: an agent built end to end on screen — calling external and legacy REST APIs, moving data through Excel and SQL, extracting unstructured data, generating the PowerPoint, and deploying to Teams under a governance checklist.

2.1 Agent Anatomy & Generative Orchestration ~40 min

  • Topics and their descriptions vs generative orchestration — when to use which
  • Instructions that constrain behaviour reliably
  • Knowledge sources: SharePoint, files, Dataverse — and freshness
  • Reading the orchestration trace to debug why the agent chose what it chose
  • Evaluating a change — test sets, scores and a repeatable before-and-after, so an improvement is a number rather than an impression
Live demo — rebuild the Module 1 assistant with generative orchestration and citations; trace one wrong answer, fix it on screen, then run a test set before and after the fix to show the change actually helped.

2.2 Actions: Calling External & Internal / Legacy REST APIs Your gap ~55 min

  • Prebuilt connectors vs Power Automate flows vs custom connectors — the decision
  • Wiring a REST call: endpoint, auth, request shape, parsing the response
  • Reaching an internal / legacy system: gateways, on-prem data, service accounts
  • Error paths, empty results, timeouts — and never guessing missing data
Live demo — the agent calls a market/fund-data REST API live, then a mock internal API standing in for a legacy system; both responses parsed into the conversation.

2.3 Moving Data Through Excel & SQL ~35 min

  • Reading a holdings / performance workbook into an agent action
  • Querying a SQL source for reference and benchmark data
  • Writing results back to a system of record
  • Keeping numbers system-sourced and narrative model-generated — never the reverse
Live demo — join the API response to an Excel holdings extract and a SQL benchmark lookup, producing one clean structured record set.

2.4 Unstructured → Structured Extraction Key ~40 min

  • The step your developers do by hand today — automated
  • Extracting fields from fund factsheets, manager updates, PDFs
  • Enforcing an output schema so downstream steps can rely on it
  • Validation, confidence and the "flag it, don't invent it" rule
Live demo — a sample fund factsheet (PDF) goes in, a validated structured record comes out; a deliberately messy document shows the failure path and the flag.

2.5 Generating the PowerPoint Report Your gap ~45 min

  • Replacing the manual conversion + Aspose + custom-code path
  • Template-driven deck generation from the structured record
  • Charts, tables and commentary assembled into the house format
  • What stays in code, what moves to the agent — an honest split
Live demo — the agent produces a finished investment report deck end to end, from factsheet input to delivered PowerPoint file.

2.6 Deploy, Trigger, Share and Govern Key ~50 min

  • Publishing the agent and deploying it into Teams where the team already works — and into Microsoft 365 Copilot via the organisation catalogue, which is an administrator-approved route
  • Sharing the agent: users, roles, co-authors, environments
  • Running it without being asked — an automated trigger fires the agent when a document arrives, so the work happens inside the process rather than in a chat window
  • Designing for unattended runs: no clarifying questions, flag and escalate, readable run history — and an approval gate whose shape depends on what started the chain — an agent calling a flow cannot be made to wait while a person decides, so that gate is asynchronous by design; a flow started by a document can wait, and does
  • Governance checklist: DLP, tenant data boundary, connector approval, audit trail, human-in-the-loop, dev → test → prod
Live demo — publish, deploy to Teams, share with a second user; then a factsheet is dropped into a SharePoint library and the agent extracts, enriches, builds the deck and raises an approval card with nobody at the keyboard. Finally the governance checklist, walked item by item against what was just built.

2.7 Consolidation, Roadmap & Open Q&A ~20 min

  • The capstone consolidated: the whole chain walked through once more, with every stage traced back to the session that built it
  • What Copilot Studio should not be asked to do
  • Sizing the effort and building the internal ROI case
  • Roadmap: POC → pilot → production, and when to go code-first (Agent Framework)

Capstone — The "Investment Report Agent"

One flagship agent, built live across Module 2 and consolidated at the end. It replaces the team's current manual unstructured → structured conversion + Aspose libraries + custom code reporting pipeline.
  • Ingest — fund factsheets / manager updates (unstructured)
  • Extract — validated structured records against a schema
  • Enrich — external market API + internal/legacy API + Excel + SQL
  • Generate — the investment report PowerPoint, house format
  • Deploy — published to Teams, shared with the team
  • Govern — DLP, audit, human review gate before client issue
Outcome split: all 35 are in the room for the whole build and leave AI-literate, able to see exactly where agents fit their workflow; the ~10 developers leave with a working proof-of-concept pattern they can rebuild in their own environment, and everyone else with a reference for what it takes.
To anchor the capstone on your real work: we ask for one concrete use case plus a sample API and dataset ahead of the session — the Aspose/PowerPoint reporting pipeline is the natural candidate. If nothing can be shared in time, the demo runs on synthetic fund factsheets and mock APIs we provide, with no impact on the agenda.
