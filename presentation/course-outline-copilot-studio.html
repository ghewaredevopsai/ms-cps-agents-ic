AI Agents for Investment Consulting

Hands-on Microsoft Copilot Studio — every session is a use case, built live on screen
1 day · ~3 hrs + ~5 hrs | Experienced practitioners | Microsoft-only, by governance | Trainer: Rajesh Gheware
The test for the day: participants leave able to build an agent that sits inside a workflow, not beside it — not merely better at prompting. Module 1 is pitched at the whole team and ends with a working agent. Module 2 extends that same agent to the point where a document landing in a library runs the chain with nobody at the keyboard. Nothing is provisioned: the trainer builds on screen and participants may follow along if they wish.
Module 1 — Foundations ~3 hrs · the whole team · eight use cases View slides →
 Use caseWhat goes in → what comes out
1.1A reusable extraction prompt A fund factsheet → 26 named fields. The two figures the document does not carry are listed as unresolved, not invented — which is the whole point of the exercise.
1.2Manager update → house question list A quarterly manager letter → the questions your own process says to ask of it, in your order.
1.3Meeting notes → decisions, actions, owners Raw notes or a Teams recap → a circulated record with an owner against every action.
1.4Holdings extract → data-quality check A holdings workbook → the rows that do not reconcile, flagged rather than quietly corrected.
1.5Draft commentary → house tone A rough paragraph → house style, with any claim it cannot support marked instead of smoothed over.
1.6Drift, fabrication and the grounding fix One fund question through three prompts — the room watches the answer drift and a figure get invented, then watches grounding fix it and sees exactly what grounding still leaves to you.
1.7Marking up your own workflow Your reporting pipeline drawn on screen → each step marked prompt-only, agent-suitable or human-only, then four criteria applied to pick the first agent actually worth building.
1.8Your first agent A three-click agent over a document library that any non-developer can repeat unaided — then the Fund Research Assistant built from empty, grounded, tested and corrected live.
Module 2 — Building It ~5 hrs · all present, build depth pitched at the ~10 developers · one agent, seven steps View slides →
 Use caseWhat is built, and what it proves
2.1Orchestration, and proving a change helped Trace one wrong answer and fix it — then score a test set before and after. Sometimes the number says the change earned nothing, which is the honest lesson.
2.2Calling external and legacy APIs A live public endpoint and a stand-in for a legacy internal system, both parsed into the conversation; error paths, empty results and timeouts included.
2.3Excel and SQL A holdings workbook and a benchmark table reached as actions, so totals, averages and currency conversion come from a system rather than from the model.
2.4Unstructured → structured Factsheet → a validated 25-key record. What it cannot confirm lands in needs_review with a reason — the step your developers do by hand today.
2.5Generating the report The structured record → a six-slide plan → a real PowerPoint file, replacing the manual conversion and Aspose step. What stays in code is stated honestly.
2.6Deploy, trigger, share, govern Published to Teams and Microsoft 365 Copilot; shared; then a factsheet dropped into a library runs the whole chain unattended and raises an approval card. Governance walked item by item against what was just built.
2.7Consolidation The capstone consolidated: the whole chain walked through once more, with every stage traced back to the session that built it. Plus what Copilot Studio should not be asked to do.
Capstone — the quarterly fund review. One agent carrying 6 actions, 3 knowledge sources and 7 flows, assembled across Module 2 rather than demonstrated separately: ingest an unstructured document, extract a validated record, enrich it from an external API, a legacy system, Excel and SQL, generate the deck, and put a human approval gate in front of anything that reaches a client. The full build sheet is a separate page participants keep, so the whole agent can be rebuilt at their own pace.

Deliberately excluded

  • No licensing or SKU theory
  • No AI history for its own sake — one slide places Copilot Studio on the ML → generative → RAG → agentic path, and that is all
  • No hype — model behaviour only where it changes what you build
  • No non-Microsoft tooling — nothing you cannot run under current governance. Agent Framework is positioned as the graduation path, not built

How it is delivered

  • No participant lab — the trainer builds live in Copilot Studio on screen
  • No dependency on tenant readiness — no DLP allow-listing, connector licensing or egress prerequisites
  • Following along is optional and needs nothing provisioned
  • For online seats: a feed of the Copilot Studio window itself, a facilitator watching chat, and recordings of the demo segments
  • Hands-on in your own environment is a follow-on engagement, separate scope

What participants keep

  • Both decks — Module 1 · Module 2 — with per-slide notes
  • The prompt-demos run-sheet — the seven prompt use cases, nothing provisioned
  • The reference pack — ten consulting prompts, a capability→workflow map, and all eight surfaces, including those the non-developer majority can use with no environment
  • The tooling pack — the same agent as files, on the command line
  • A pre-read watchlist sent the evening before — ten videos, four marked as the ones that matter
  • Demo assets: synthetic factsheet, workbooks, mandate and FX payloads, SQL script, slide-plan schema and a working plan→deck renderer
