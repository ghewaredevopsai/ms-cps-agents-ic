Why the middle column, for you

  • It explains the pilot result precisely: Copilot was asked to do a job that needed the middle column. The writing was never the problem — the reach was.
  • The effort stars are about who can build and maintain it, not about capability. Foundry is the most capable and the least likely to be right for a first agent.

Not a migration — they coexist

  • Copilot keeps doing individual drafting. Agents take the repeatable pipeline work. Same tenant, same policy, same day.
  • Moving right is a decision you make on evidence — Module 2 closes with the five signals that say it is time, and almost nobody should start there.

The rung inside the left column

  • An agent scoped to one SharePoint library, made from the library in a few clicks — named, cited and shareable, with no canvas and no environment. You can build one this week; it is shown for three minutes before the build.
  • It reads that library and nothing else: no system call, no trigger, no deck, no trace. Those four gaps are the middle column's entire job.
Same login, same tenant, same data boundary. None of this is a new vendor decision — which is exactly why it fits inside your current governance.

Why the Copilot pilot did not move the numbersPRE · DEMO 1.71.3

The diagnosis

  • The pilot was not badly run and the team was not wrong about the tool. It was measured against pattern B while only pattern A was possible.
  • Pattern A gains are individual and hard to see in a process metric. They also do not compound.

What unlocks pattern B

  • Permission for the agent to call a system — the connector and DLP conversation.
  • An owner for the agent, and a place for it to run.
  • One approval gate the business trusts, so autonomy is bounded rather than debated.
This is the honest answer for your stakeholders: the pilot proved the model works. It could not prove the process changes — because nothing was allowed to touch the process.
