AI Agents for Investment Consulting — Microsoft Copilot Studio
1 Day · 27 August 2026 | Investment Consulting | 7 demos | Trainer: Rajesh Gheware
Use synthetic data only. Every demo in this guide runs on the supplied Northwind Multi-Asset Growth Fund factsheet — a fictional fund created for training. Do not paste real client, fund, member or corporate data into any agent you build while following along, and never into a trial or personal tenant. If you are unsure whether your environment is approved for a piece of data, the answer is to use the synthetic file.

How to use this guide

Two documents, one agent, no overlap. This guide is the run-sheet: what each demo proves, what to type, what you should see, and what to do when it misbehaves. The build sheet is use-cases/fund-research-assistant.html — every flow node, every expression, every instruction block, in build order. Demos 1.8 and 2.1–2.7 all extend the same agent, and each one points at the stage that builds it. Configuration is written down once, on that page.

The workshop is trainer-led: Rajesh builds everything live on screen. Nothing here is required of you, and no lab has been provisioned. This guide exists so that if you want to build alongside the demo — on the day or afterwards — you can, without pausing the room to ask what was clicked.

Every demo below is written to the same shape: what it proves → what you need → the steps → the exact text to paste → what you should see → what to do when it breaks.

If you fall behind, stop building and start watching. Every demo states what you should see, so you can read the outcome without having produced it, and the assets are yours to keep — the afternoon is not a race and nothing later depends on your having finished something earlier.

Demo 1.1 A reusable extraction prompt AB~12 min
What it proves: a prompt with named fields and a fixed output shape produces the same table every time — which is what makes the next step automatable. A vague prompt does not.
You need

A bare surface with no Instructions — a scratch Copilot Studio agent with an empty Instructions box is the most reliable, and Copilot chat works if your tenant will fabricate. sample-fund-factsheet.pdf attached. Nothing has been built yet, and that is the point: everything you see here is the prompt doing the work, unaided. On the Fund Research Assistant page this same prompt becomes an agent’s Instructions.

Steps
  1. Ask badly first. Paste the vague prompt. Look at what you get back.
  2. Run it again in a new chat. The shape of the answer will have changed — different headings, different emphasis, different fields.
  3. Now ask properly. Paste the structured prompt. This is the five-part prompt from the slide: role, context, task, format, example.
  4. Run it twice more. Confirm you get the same table each time.
The vague prompt (run this first, so the contrast lands)
Summarise the key points of this fund factsheet.
The structured prompt
You are an investment consultant preparing a quarterly fund review for an
institutional client - a long-horizon retirement portfolio.

Use only the attached Northwind factsheet (data as of 30 June 2026).
If a value is not present in the document, write: not stated.
Do not estimate, infer or calculate any figure.

Extract exactly these fields:
  fund name, ISIN, share class, fund size (AUM), benchmark, fund manager,
  inception date, TER regular, TER direct, exit load,
  return 1yr, return 3yr, return 5yr, return since inception,
  benchmark 1yr, benchmark 3yr, benchmark 5yr,
  equity allocation, debt allocation, gold allocation, cash allocation,
  top holding name, top holding weight,
  tracking error, portfolio turnover, NAV per unit

Return a markdown table with exactly three columns: field | value | source section.
One row per field, in the order listed above.

Example row:
TER direct | 0.62% | Section 9 Fees
What you should see
  • The vague prompt gives you a readable paragraph or bullet list — useful to a human, useless to a downstream step, and different every run.
  • The structured prompt gives you 26 rows, in your order, with a source column. Run it three times and the table is stable.
  • The last three rows read not stated. Tracking error, portfolio turnover and NAV per unit are deliberately absent from the factsheet — they are there to prove the refusal line is doing work. Stage 1 of the agent page deletes that line and shows what fills the gap.
When it does not behave
  • Fields are merged or reordered. Add "Do not merge, rename, reorder or omit any field. If unsure, output the field with value: not stated."
  • You get prose instead of a table. Some interfaces need the format demand repeated at the end. Append: "Output the markdown table and nothing else."
  • The ISIN looks wrong. It should be INF000SAMPLE01 — the factsheet marks it illustrative. If you got a real-looking ISIN, the model invented it.
  • Step 5 changed nothing — the fields still read not stated. Expected in Microsoft 365 Copilot chat with a file attached: it will not invent a field value whichever instruction you delete, and it emits not stated on its own as its convention for an absent field. Deleting the second guard as well makes no difference. Run step 5 against a Copilot Studio agent with Allow ungrounded responses on, or present it as a walkthrough rather than a live result.
Carry this forward

Save this prompt. On the agent page that same discipline becomes an enforced schema over a slightly different field list — at which point "not stated" stops being a request and becomes a rule the system checks.

Demo 1.2 Manager update → the house question list AB~5 min
What it proves: the five parts are not specific to factsheets. Same anatomy, a different document, and a fixed question list — which is what makes manager A and manager D comparable at all.
You need

The same bare surface as demo 1.1 — still no Instructions — with meridian-manager-update.txt attached (it is in demo-assets/). It is also the second knowledge source on the Fund Research Assistant, but run this one outside that agent for the same reason as 1.2.

Steps
  1. Ask badly first. "What does this manager update say?" You will get the manager’s own emphasis, in the manager’s own order.
  2. Now paste the structured prompt. Same five parts as the slide, pointed at a different job.
  3. Read the headings, not the prose. They are in your order now, and one of them should say Not addressed.
The prompt
You are an investment consultant reviewing a manager's quarterly update
for an institutional client.

Use only the attached manager update (July 2026). If the update does not
address something, write: not addressed. Do not infer it from tone.

Answer the house question list, in this order:
  1. what changed in the team
  2. what changed in the process
  3. what drove performance this quarter
  4. the manager's own explanation of the worst quarter

One heading per question. Two sentences maximum under each.
Write "Not addressed" wherever the update is silent.

Example:
Team - Two analysts left the credit desk in May; no replacement named. Section 3
What you should see
  • Four headings, in the order you asked for — not the order the manager wrote in.
  • At least one Not addressed. That is the finding: the thing the update quietly skipped is now visible instead of absent.
  • Run it against a second manager update and the two are comparable line for line. That is the whole point of a house list.
When it does not behave
  • It answers in the manager’s order. Repeat the constraint at the end: "Answer the four questions in the order given, even where the update covers them in a different order."
  • It infers a reason from tone. The CONTEXT line is doing the work. Strengthen it: "If the update does not state a reason, write: not addressed. Do not construct one."
Demo 1.3 Meeting notes → decisions, actions, owners AB~5 min
What it proves: the FORMAT line is the whole value here. Three lists with an owner-and-date rule turn a readable summary into a record somebody can be held to.
You need

Nothing attached. Same bare surface — paste the synthetic notes below, then the prompt underneath them.

Steps
  1. Paste the notes. They are deliberately messy, the way real notes are.
  2. Paste the prompt. Note that it demands an owner and a date on every action line.
  3. Count the not stated entries. Those are the actions that would have quietly gone nowhere.
The notes to paste first
IC meeting, 14 July. Present: three of five.
Northwind - 3yr 15.6% vs benchmark 13.1%. Committee comfortable. Equity 68%,
mandate ceiling 70%, agreed to keep watching but no action for now.
Someone to get the latest fee schedule off the manager - direct plan TER
looked like 0.62% but nobody had it in writing. Before end of September.
Question raised about whether the gold sleeve is still doing anything.
Parked. Agreed to revisit the whole allocation at the October meeting.
Chair asked for the Q3 pack a week earlier than usual this time.
The prompt
You are the secretary of an investment committee, writing the record
for people who were not in the room.

Use only the notes above. Do not add context you believe to be true but
that nobody actually said.

Separate the notes into three lists: decisions taken, actions agreed,
and questions left open.

Three headed lists. Every action line carries an owner and a date. Where
either is missing, write: owner not stated, or: date not stated.

Example:
Action - Request the fee schedule from the manager | Owner: not stated | By: 30 Sep
What you should see
  • Three lists, and the split is cleaner than the notes felt.
  • The fee-schedule action comes back as owner not stated. In the notes it reads as agreed; in the record it reads as nobody’s job. That is the demo.
  • The gold-sleeve question lands under open, not under decisions — "parked" is not a decision.
When it does not behave
  • It invents an owner. Usually the chair. Add: "Never attribute an action to a person who is not named in the notes."
  • It merges decisions and actions. Add one line of definition: "A decision is a conclusion reached. An action is something a named person must do."
Demo 1.4 Holdings extract → data-quality check AB~5 min
What it proves: the CONTEXT line holding the arithmetic back. This is the task where totalling the column is most tempting and a wrong total is least visible.
You need

Same bare surface. holdings.xlsx from demo-assets/, or just paste half a dozen rows of it — either works.

Steps
  1. Paste the prompt with the holdings rows.
  2. Check what it did not do. It should flag rows and refuse to total the weight column.
  3. Optional, ~30 seconds: delete the sentence beginning "Do not calculate" and run again. Watch a total appear that nobody asked for and nobody will re-add.
The prompt
You are a portfolio analyst checking a holdings file before it is used
in a client report.

Use only the rows in the attached extract. Do not calculate totals,
averages or weighted figures, and do not convert currencies.

Flag: duplicate identifiers, missing sector or currency, blank weights,
and any row whose currency differs from the fund's stated currency.

Return a table - row number | field | what is wrong | why it matters.
Nothing else: no summary, no total row.

Example:
14 | currency | blank | cannot be aggregated or converted
What you should see
  • A table of flagged rows, and no total anywhere.
  • If a total appears, the CONTEXT line was dropped or overridden. That is worth showing deliberately — the number will look entirely reasonable.
  • This is the same tiered rule as the rest of the day: the model may state a difference between two figures it can show you; totals, averages and weighted figures come from an action.
When it does not behave
  • It totals the weights anyway. Move the refusal to the last line of the prompt. Position matters more than wording here.
  • It invents a sector for a blank cell. Add: "A blank cell is a finding, not a gap to fill."
Demo 1.5 Draft commentary → house tone, figures frozen AB~5 min
What it proves: one worked line settles tone faster than a style guide — and that a rewrite is the easiest place in the day to lose a number without noticing.
You need

Nothing attached. Same bare surface — paste the draft below, then the prompt.

Steps
  1. Paste the draft. It is deliberately written in the wrong voice.
  2. Paste the prompt, including the worked example line.
  3. Compare the figures, not the prose. Every number in the output should be byte-identical to the draft.
The draft to paste first
The fund had a truly excellent three years, delivering a stellar 15.6%
annualised and comfortably crushing its benchmark's 13.1%. Equity exposure
ended the period at a healthy 68%, and we remain very confident that this
positioning will continue to reward patient investors going forward. Fees
remain highly competitive at 1.18% regular and just 0.62% direct.
The prompt
You are writing quarterly commentary in your firm's house voice
for an institutional client.

Use only the figures in the draft above. Do not change, round or
re-express any number, and do not add a figure that is not already there.

Rewrite the draft in house tone: plain, specific, no superlatives,
and no forward-looking claims.

Three paragraphs, 120 words maximum each. Every figure exactly as written.

Example of house tone:
The fund returned 15.6% over three years, against 13.1% for the benchmark.
What you should see
  • “Truly excellent”, “stellar”, “crushing” and “healthy” all gone; the sentences got shorter and more specific.
  • The forward-looking claim disappears — "we remain very confident this positioning will continue to reward" is exactly the sentence a consultant cannot sign.
  • 15.6, 13.1, 68, 1.18 and 0.62 all survive untouched. Check them one by one. This is the failure to watch for, because rounding reads as tidying.
When it does not behave
  • 15.6% becomes “approximately 16%”. The most common failure, and the most plausible-looking. Repeat the constraint last: "Quote every figure exactly as it appears. Do not round."
  • It keeps a superlative you did not notice. Give it the list: "Remove: excellent, stellar, strong, robust, healthy, comfortably, significantly."
Demo 1.6 Drift, fabrication and the grounding fix AB~10 min
What it proves: the same question, asked three ways, produces three different levels of trustworthiness — and only the grounded version is safe to put near a client deliverable.
You need

Any chat interface to a model you are permitted to use — but prefer the Copilot Studio test pane. On a cautious tenant Microsoft 365 Copilot invents a figure close to the real one (~17% against a true 15.6%) and the contrast barely registers; an agent typically invents 5–7%, which is visibly wrong. The factsheet file for step 3.

Steps
  1. Ask with no context at all. Open a fresh chat and paste prompt A. Note the answer.
  2. Ask again in a new chat. Paste exactly the same prompt A a second time. Compare the two answers word by word.
  3. Now ground it. Attach sample-fund-factsheet.pdf to the chat and paste prompt B. Compare against what the document actually says.
  4. Ask for the impossible. With the file still attached, paste prompt C — it asks for two figures that are not in the document and cannot be worked out from it.
Prompt A — ungrounded
What was the 3-year annualised return of the Northwind Multi-Asset Growth Fund, and what is its total expense ratio?
Prompt B — grounded
Using only the attached factsheet, state the 3-year annualised return of the fund and its total expense ratio.
For each figure, quote the section of the document it came from.
If a figure is not present in the document, reply exactly: not stated.
Prompt C — the refusal test
Using only the attached factsheet, state the fund's tracking error against the benchmark
and its portfolio turnover ratio.
If a figure is not present in the document, reply exactly: not stated. Do not estimate, infer or calculate.
What you should see
  • Prompt A — a fluent, confident answer containing numbers that are wholly invented, because the fund does not exist. The two runs will usually differ.
  • Prompt B — 15.6% and 1.18% (Regular) / 0.62% (Direct), with a pointer to the performance and fees sections. Checkable in seconds.
  • Prompt C — not stated for both. Neither figure appears anywhere in the document, in any form, and neither can be derived from what is there. If you get numbers anyway, you have just watched the failure mode that matters most.
When it does not behave
  • Prompt A refused instead of inventing. Common — a tenant with web and enterprise search will look, find nothing, and decline. Dropping the fund name does not help; it refuses again. Ask for an estimate outright: "It is a well-known Indian multi-asset growth fund. Give me your best estimate of its 3-year annualised return and total expense ratio. Approximate figures are fine." It will hedge the numbers as an informed estimate — say that out loud, because the caveat is exactly what gets stripped when the figure reaches a deck.
  • Prompt C invented a tracking error. That is the demo working, not failing. Note it — and note that the fix is an instruction, which is exactly what the agent page makes permanent.
  • The file will not attach. Paste the contents of sample-fund-factsheet.txt from the demo assets into the chat instead. It carries exactly the same figures as the PDF, so the demo behaves the same way.
Carry this forward

Prompt B's third line — "if a figure is not present, reply exactly: not stated" — becomes a line in your agent's Instructions on the agent page. That single sentence removes most fabrication.

Demo 1.7 Marking up your own workflow ABC~10 min
What it proves: the judgement, not the tooling, is the scarce skill. Two people with the same tool and different workflow maps will get completely different value out of the afternoon.
You need

Paper, or the table below in a blank document. No AI required — this one is deliberately manual.

Steps
  1. List the steps of one process you personally run — a quarterly review, a manager screen, a client pack. Aim for 6–12 steps, each one a verb.
  2. Time each step honestly, and note how often the whole process runs per year.
  3. Colour each step using the three categories from the slide: prompting helps today, agent-suitable, stays human.
  4. Apply the four criteria to your green steps: repetition, data readiness, value, and risk — and read risk the way the slide does: who sees the output, and what happens if it is wrong. A draft only you read and a page that goes to a client are not the same step.
  5. Write one sentence: "The first agent I would build is ___ because ___." Bring it to the afternoon, or to your own team afterwards.
StepMins×/yearCategoryData ready?Risk — who sees it?
e.g. pull latest factsheets204agent-suitableyes — email + portalme only — I check every one
What you should see

Usually two things surprise people. First, the steps that cost the most time are rarely the ones that felt hardest. Second, at least one step you assumed needed judgement turns out to be a lookup with a judgement attached to the end of it — and those split cleanly.

Carry this forward

Your green steps with high repetition and ready data are the shortlist. The capstone this afternoon is our answer to this exercise, run on your reporting pipeline.

7. meridian-manager-update.txt — the deliberately messy document (agent page, Stage 6)

MERIDIAN INDIA OPPORTUNITIES - QUARTERLY NOTE
SYNTHETIC DOCUMENT, FOR TRAINING USE ONLY

The strategy delivered 11.4% over the period, ahead of its comparator. Assets
under management stood at approximately Rs 1,900 crore at quarter end, up from
the prior quarter.

Charges are 1.05% on the regular plan; the direct plan is lower. Investors
should refer to the scheme information document for the current figure.

The portfolio remains equity-oriented with a modest allocation to cash. The
manager has run the strategy since launch.

Note: figures are unaudited and subject to revision.

Deliberate traps: "the period" is never defined — 1 year? the quarter? · the direct-plan TER is described but never given · there is no ISIN, no benchmark name, no inception date, no allocation percentages · "approximately" Rs 1,900 crore. A good extraction returns roughly eighteen not stated values out of the 25 keys and a populated needs_review. A bad one fills the gaps for you.

8. benchmarks-sql.sql — the benchmark database (agent page, Stage 5)

Creates dbo.Benchmark, loads the three synthetic indices, and creates the two stored procedures shown on the slide: usp_GetBenchmarkReturns returns one typed row, and usp_GetExcessReturn does the subtraction in the database rather than in the model. Runs unchanged on Azure SQL Database free tier or SQL Server 2019+. Roughly five minutes to stand up, and it is the fastest way to reproduce the SQL half in your own environment.

9. slide-plan-sample.json — a finished slide plan (agent page, Stages 6–7)

Six slides, every figure carrying a source, and two entries in unresolved — tracking error and portfolio turnover, the two fields the factsheet genuinely does not contain. Compare your agent's plan against this one. If yours has fewer unresolved entries than this, that is not a better agent; check where the extra numbers came from.

10. deck-renderer.html — plan in, deck out (agent page, Stages 6–7)

A single self-contained page: open it in any browser, press Load plan.json, and it renders the plan as a printable deck. No install, no licence, no tenant, no connector. It exists to make one point — once the plan is a validated contract, whatever renders it is an implementation detail. In your environment the renderer is the Aspose generator you already own; here it is a browser page. The agent does not know the difference, and that is precisely why the architecture is a good one. It also warns you, in red, if any figure in the plan arrives without a source.

11. investment-report-sample.pptx / .pdf — the capstone output

Item 9 rendered twice — by item 12 into an editable PowerPoint file, and by item 10 into the PDF. This is the artefact the whole day is pointed at: the deck that today is assembled by hand, through six hand-offs, from a factsheet, a workbook, a benchmark lookup and a mandate system. The last page is the one to look at — it lists what the agent could not source and therefore refused to put on a slide.

12. plan-to-pptx.py — plan in, PowerPoint out (agent page, Stages 6–7)

The last hop, in one file. pip install python-pptx, then python3 plan-to-pptx.py slide-plan-sample.json deck.pptx. It writes a real, editable PowerPoint file — a native chart you can click into, a real table, every figure carrying its source, and a closing slide built from unresolved. No tenant, no connector, no licence. For a PDF afterwards: soffice --headless --convert-to pdf deck.pptx. Two details worth opening the code for. It shrinks type rather than let text overflow its box, because the library cannot compute autofit — that is the defect which finds every report generator the first time real commentary runs longer than the sample. And it refuses to print a source line it does not have, which is the schema's discipline carried one step further down the pipeline.

One failure from hosting it, worth more than the script. Behind an HTTP endpoint, the first call driven by the agent returned 500 with an empty body while the same code had just succeeded on the sample plan. The agent had titled the deck with an em-dash, the handler put that title into a Content-Disposition header, and HTTP headers are Latin-1 only — the response died before it was written. Every local test had passed, because every local test used the ASCII fixture. Test the last hop with the agent's own output, not with your sample file. Model output routinely carries em-dashes, curly quotes and non-breaking spaces; your fixture never does.

Troubleshooting — the fourteen things that actually go wrong

SymptomCause and fix
Agent answers from general knowledgeOne of the two Generative AI switches is still on — Allow ungrounded responses and Use information from the Web — or the knowledge files have not finished indexing. Fix both, wait for file status to show ready, and always retest in a new conversation.
It still cites the web with both switches offThe Conversational boosting system topic is enabled and answering from a generative fallback. Topics → System → switch it off. If a system fallback topic is also swallowing retrievals that plainly succeeded, disable that while debugging and restore it afterwards.
An Instructions edit lands in the wrong placeDo not append to the end of the box — jumping to the end of that editor is unreliable and will drop your new block into the middle of an existing rule, splitting it. Replace the whole Instructions block, then read the stored value back to confirm it. The character counter goes stale and will tell you the edit worked when it did not.
Instruction changes have no effectYou saved but tested in an existing conversation. Start a new one. This costs more workshop time than any other single issue.
The agent never calls your actionThe action description does not say when to use it. Rewrite it as a sentence a colleague would understand, and name the trigger conditions.
Excel connector cannot see the dataThe range is not formatted as a Table (Ctrl+T), or the file is in personal OneDrive rather than OneDrive for Business.
Flow succeeds, agent ignores the resultThe Respond step is not returning the value as text the agent can read. Test the flow standalone in Power Automate first — always isolate before you debug the agent.
A flow the agent called fails on its last stepActionResponseTimedOut or an HTTP 504 on Respond to the agent means the flow took too long. An agent-called flow has roughly 100 seconds, so anything that waits on a human — an approval, a form — will always fail there, even though the step it waited on succeeded. Split it: one flow starts the work and answers immediately, a second reads the result back later.
"Premium connector required"Expected for HTTP and SQL. Use the Compose substitutes in the appendix — you keep the whole lesson and lose only the live call.
JSON output will not parseA preamble sentence or a markdown fence. Add: "Output must begin with { and end with }. No other characters."
An automated trigger never firesSharePoint and OneDrive triggers poll; they do not push. Allow a minute, and longer for a flow's first run. Read the run history before changing anything — most "broken triggers" are impatience.
An evaluation score improved and you cannot say whyYou changed more than one thing between runs. Re-run the baseline, change a single instruction, source or model, and run the identical set again. A score you cannot attribute is not evidence — and it is worse than no score, because it feels like one.
The agent does arithmetic it was told not toCheck which rule it broke. A difference between two figures it showed you is allowed; a total, an average or a conversion is not. If it produced one of those, no action was returning the number — build the action rather than sharpening the sentence.
Everything is blocked in your tenantYou are Track C, and that is a legitimate outcome, not a failure. Watch, keep this guide, and replay in a developer tenant afterwards — every asset you need is shipped as a real file alongside this guide.

After the workshop — taking this into your own environment

Everything you built today lives in a training environment on synthetic data. Rebuilding it against your own systems is a separate piece of work with real dependencies. These are the six conversations to start, in this order:

  1. An environment. A Power Platform environment your team owns, with dev and prod separated. Ask for this first — everything else waits on it.
  2. Connector approval and DLP. The specific list of connectors your agent needs, and which data groups they sit in. This is the dependency with a queue in front of it, so start it early.
  3. An identity for the agent. How it authenticates to your internal and legacy systems — a service principal, a gateway, or an API wrapper around what exists.
  4. Data classification, not just DLP. DLP governs which connectors may combine; it says nothing about the sensitivity of what the agent reads and writes. Two questions for your information-protection owner: can a user be cited to a document they may not open (with user authentication, no — results trim to the asker), and does a generated deck inherit the label of its most restrictive source (no — it carries no label until something applies one). The second is the gap: decide who labels the output before the first client deck exists.
  5. A named owner and reviewer. Not a formality: an agent nobody owns stops being maintained within a quarter, and an approval gate with no time behind it is theatre.
  6. The publishing route. Teams you can usually reach yourself. Microsoft 365 Copilot goes through the organisation catalogue and an administrator's approval queue — so find out who holds that queue and what they need from you. Ask in week one; it is the request that decides your launch date, not your build.
Bring your workflow map from demo 1.7 to that conversation. A request framed as "we want to remove four steps from the quarterly review, here is the map and here is what it needs" lands very differently from "we would like to try Copilot Studio".

Three defects that will find you the first time you write to Dataverse

Nothing today writes to Dataverse — the capstone stages everything in SharePoint on purpose. In your own environment it will be a Dataverse table soon enough, and these three cost an afternoon each the first time:

What you seeWhat is actually wrong
A choice column rejects the write, or silently stores the wrong optionYour form or card collects the choice label as text ("High"); Dataverse stores the choice value as a number. Map it explicitly — set a variable with a Power Fx Switch(Topic.Priority, "Low", 1, "Medium", 2, "High", 3, "Critical", 4, 1) and write the variable, not the label.
The write errors on a field you have clearly mappedYou bound the whole record where the column wants a field. Pick the field explicitly — TicketTitle.Text, not TicketTitle. The designer reports this unhelpfully, so check every binding rather than hunting the message.
A lookup column will not accept anything you give itLookups want the OData form, not a name or a GUID on its own: /contacts(<guid>). Get the GUID with a List rows step filtered on emailaddress1 eq '<System.User.Email>', coerce it to text, then build the string. System.User.Email is also the cleanest hook for “who is asking” — the identity question from session 2.2, answered concretely.
