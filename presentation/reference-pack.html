Part 1 — The consulting prompt pack

Ten prompts that do work this team actually does. They are written against the Northwind Multi-Asset Growth Fund material used all day, so you can run any of them immediately and see the expected answer; swapping in your own document is a find-and-replace.

These are meant to become team assets, not personal snippets. A prompt that lives in one person's chat history is worth one person's time. The same prompt, owned, named, versioned and pasted by twelve people, is worth twelve — and it is the only version anyone can improve. Put them somewhere shared before you start editing them. Where you have AI Builder available, a prompt with a defined output schema is the governed form of the same thing — the shape is then enforced by the platform rather than requested by a sentence.

The five rules every prompt below obeys

RuleWhy, in this business
Name the sourceAsk for a source column or a citation on every figure. An unsourced number is not evidence, however confident it sounds.
Give it permission to failWithout an explicit refusal line, the model fills a gap rather than reporting one. A fabricated tracking error looks exactly like a real one.
DecomposeExtract, then check, then write. One prompt that does all three does none of them reliably.
Keep it out of the arithmetic that mattersIt may state the difference between two figures it has retrieved and shown you with their sources. Totals, averages, weighted figures and currency conversion must come from a system — a workbook, a query, an action.
Fix the output shapeA table with named columns can be checked, pasted and automated. A paragraph can only be read.
Before you paste anything real. Everything in this pack is written against synthetic training data. Whatever you run these in, apply the rule you already apply to any other tool: no client, fund, member or scheme data goes anywhere it is not approved to go, and never into a trial or personal tenant. If you are unsure whether a surface is approved, that is a question for your information-protection owner and it is worth asking before the first useful answer, not after.
1 — Factsheet → structured recordthe spine of everything else EXTRACTION
Use when you need the same fields off every factsheet, every quarter, in a shape the next step can rely on.
What was the 3-year annualised return of the Northwind Multi-Asset Growth Fund, and what is its total expense ratio?
Prompt B — grounded
Using only the attached factsheet, state the 3-year annualised return of the fund and its total expense ratio.
For each figure, quote the section of the document it came from.
If a figure is not present in the document, reply exactly: not stated.
Prompt C — the refusal test
Using only the attached factsheet, state the fund's tracking error against the benchmark
and its portfolio turnover ratio.
If a figure is not present in the document, reply exactly: not stated. Do not estimate, infer or calculate.
What you should see
  • Prompt A — a fluent, confident answer containing numbers that are wholly invented, because the fund does not exist. The two runs will usually differ.
  • Prompt B — 15.6% and 1.18% (Regular) / 0.62% (Direct), with a pointer to the performance and fees sections. Checkable in seconds.
  • Prompt C — not stated for both. Neither figure appears anywhere in the document, in any form, and neither can be derived from what is there. If you get numbers anyway, you have just watched the failure mode that matters most.
When it does not behave
  • Prompt A returned "I don't know". Good — some configurations are more cautious. Try it without the fund name: "What was the 3-year return of the multi-asset fund we discussed?"
  • Prompt C invented a tracking error. That is the demo working, not failing. Note it — and note that the fix is an instruction, which is exactly what demo 1.8 makes permanent.
  • The file will not attach. Paste the contents of sample-fund-factsheet.txt from the demo assets into the chat instead. It carries exactly the same figures as the PDF, so the demo behaves the same way.
Carry this forward

Prompt B's third line — "if a figure is not present, reply exactly: not stated" — becomes a line in your agent's Instructions in demo 1.8. That single sentence removes most fabrication.

Demo 1.1 A reusable extraction prompt AB~12 min
What it proves: a prompt with named fields and a fixed output shape produces the same table every time — which is what makes the next step automatable. A vague prompt does not.
You need

The same chat interface, with sample-fund-factsheet.pdf attached.

Steps
  1. Ask badly first. Paste the vague prompt. Look at what you get back.
  2. Run it again in a new chat. The shape of the answer will have changed — different headings, different emphasis, different fields.
  3. Now ask properly. Paste the structured prompt. This is the five-part prompt from the slide: role, context, task, format, example.
  4. Run it twice more. Confirm you get the same table each time.
  5. Break it deliberately. Delete the line beginning "If a value is not present" and run once more. Watch the three absent fields fill themselves in.
The vague prompt (run this first, so the contrast lands)
Summarise the key points of this fund factsheet.
The structured prompt
You are an investment consultant preparing a quarterly fund review for an
institutional client - a long-horizon retirement portfolio.

Use only the attached Northwind factsheet (data as of 30 June 2026).
If a value is not present in the document, write: not stated.
Do not estimate, infer or calculate any figure.

Extract exactly these fields:
  fund name, ISIN, share class, fund size (AUM), benchmark, fund manager,
  inception date, TER regular, TER direct, exit load,
  return 1yr, return 3yr, return 5yr, return since inception,
  benchmark 1yr, benchmark 3yr, benchmark 5yr,
  equity allocation, debt allocation, gold allocation, cash allocation,
  top holding name, top holding weight,
  tracking error, portfolio turnover, NAV per unit

Return a markdown table with exactly three columns: field | value | source section.
One row per field, in the order listed above.

Example row:
TER direct | 0.62% | Section 9 Fees

What good looks like: 26 rows in your order, stable across runs, and the last three — tracking error, portfolio turnover, NAV per unit — reading not stated. Those three are absent from the factsheet on purpose. If they come back with numbers, your refusal line is not working and nothing downstream of it can be trusted either.

2 — Manager update → the house question listmanager research EVERY WEEK
Use when a manager commentary lands and you need the four things you always need, not a summary of what the manager chose to emphasise.
You are an investment consultant reviewing a manager commentary.
Source: the attached Northwind manager commentary, July 2026.

Answer only from the attached document. Where the document does not
address a question, answer: not addressed in this update. Do not infer
an answer from what a manager would usually say.

Answer these four questions, each in no more than three sentences,
each followed by the exact sentence from the document you relied on:

1. What changed in positioning this period, and what reason is given?
2. What forward-looking statement or constraint does the manager commit to?
3. What does the manager NOT mention that a quarterly review would expect?
4. Which statements are fact as at the reporting date, and which are opinion
   about the future? Label each claim you list as FACT or VIEW.

Then list any figure in the document that would need checking against an
independent source before it is quoted to a client.

What good looks like: question 2 should surface the manager's own words on the gold sleeve — held as a drawdown hedge, with no intention of exceeding 7%. That is a commitment you can monitor against next quarter. Question 3 is the one that earns the prompt: it makes the silence visible.

The habit worth copying: the FACT / VIEW split in question 4. A commentary blends the two in every paragraph, and the distinction is exactly what a trustee needs and what a summary destroys.
3 — Meeting notes → decisions, actions, ownerscommittee and manager meetings EVERY WEEK
Use when you have a transcript or your own notes and the deliverable is a record someone will be held to.
You are minuting an investment committee meeting.
Source: the notes/transcript below. Use nothing else.

Produce three sections, in this order:

DECISIONS - only where the notes record that something was agreed, rejected
or deferred. Each row: decision | who agreed it | the wording in the notes
that shows agreement. If agreement is implied rather than recorded, put it
under DISCUSSED instead.

ACTIONS - each row: action | named owner | due date. If the notes do not
name an owner or a date, write: owner not recorded / date not recorded.
Never assign an owner yourself.

DISCUSSED, NOT DECIDED - topics raised with no recorded outcome.

Do not summarise the discussion. Do not add recommendations. Do not soften
or reword a disagreement.

4 — Holdings extract → data-quality checkbefore anything is calculated READ THE CAVEAT
Use when a holdings or performance file arrives and you want the obvious problems found before the numbers get used.
You are checking a holdings extract for data-quality problems before it is
used in client reporting. Source: the attached workbook only.

Do NOT total, average or recalculate anything. You are looking for
problems that are visible on the face of the data.

Report, as a table of issue | rows affected | why it matters:
- rows with a missing or blank identifier, name, weight or date
- weights that are negative, zero, or greater than 100
- identifiers that repeat
- as-at dates that differ from the file's stated reporting date
- any value whose format differs from the rest of its column
  (a weight as text, a date as a number, a stray currency symbol)
- any row whose weight is an order of magnitude away from its neighbours

Then add one line: "Arithmetic checks not performed - totals, weighted
averages and any cross-footing must be verified in the workbook."

If you find no issues, say so explicitly. Do not invent an issue to be useful.
Why the prompt refuses to add up the weights. It would be trivially easy to ask, and the answer would look right most of the time — which is the problem. A total that reaches a client pack must come from something that would produce the same number again tomorrow. This prompt finds the broken rows; the workbook does the arithmetic. That division is the whole rule, applied to the one task where it is most tempting to break it.
5 — Fee schedule → like-for-like, with the basis statedfee and RFP benchmarking AD HOC
Use when two fee proposals are quoted on different bases and the comparison has to be defensible.
You are comparing investment management fee proposals for an institutional
mandate. Sources: the documents provided. Use nothing else.

For each proposal, extract into a table: manager | headline fee | the basis
it is quoted on (percentage of what, and per what period) | what is stated
to be included | what is stated to be excluded | minimum or tiering | the
exact clause you took each from.

Then, in prose, list every reason these figures are NOT directly comparable:
different bases, different inclusions, tiering thresholds, performance fees,
transaction costs, anything quoted net where another is gross.

Do not convert between bases. Do not compute an effective fee, a blended
rate, or a cost in currency on any asset size. Where a comparison requires
arithmetic, state precisely which calculation is needed and on what inputs,
so it can be done in the fee model.

Where two figures are already quoted on the same basis, you may state the
difference between them, showing both figures and their sources.

Worked against the anchor: Northwind quotes 1.18% Regular and 0.62% Direct, same basis, both from Section 9 — so 0.56 percentage points is a legitimate answer with both figures shown. A cost in rupees on a given AUM is not; that is a calculation, and it belongs in the model.

6 — Position vs mandate → flag, never opinecompliance monitoring ADVICE BOUNDARY
Use when you are checking a portfolio against an investment policy or mandate document.
You are checking a portfolio's stated allocations against a client mandate.
Sources: the fund factsheet and the mandate record provided. Use nothing else.

For each limit in the mandate, produce a row:
limit | mandate value | portfolio value | source of each | status

Status must be exactly one of: WITHIN, AT LIMIT, BREACH, or CANNOT DETERMINE.
Use CANNOT DETERMINE whenever the portfolio document does not state the
figure the limit is expressed in - do not substitute a similar figure.

You are reporting, not advising. Do not state whether a breach is acceptable,
whether it should be remedied, whether the fund is suitable for this client,
or what action anyone should take. If asked for any of those, reply:
"That is an advice judgement for the consultant of record."

Worked against the anchor: the mandate caps equity at 70%; the factsheet reports 68% equity. WITHIN, with both figures and both sources shown. Minimum credit quality AA is CANNOT DETERMINE — the factsheet says the fund avoids unrated credit and holds high-grade bonds, which is not the same statement as a rating floor, and the prompt is built to notice the difference.

The closing paragraph is the same boundary the workshop builds as a topic in demo 1.8 rather than a sentence. A sentence in a prompt asks for the refusal and rewords it every time; a topic makes it fixed wording that a compliance reviewer can approve once. If this prompt becomes an agent, that is the first thing to promote.
7 — Commentary → house tone, figures frozenclient reporting EVERY QUARTER
Use when a draft says the right things in the wrong voice, and the numbers must survive the rewrite untouched.
Rewrite the passage below in the house style described, for a trustee
audience with no assumed technical vocabulary.

Absolute constraints:
- Do not change, round, restate or move any number, date, percentage,
  fund name, manager name or defined term.
- Do not add a figure that is not in the source.
- Do not add a forward-looking statement, a recommendation, or a
  reassurance that is not in the source.
- If a sentence cannot be simplified without changing its meaning,
  leave it exactly as it is and list it under UNCHANGED at the end.

House style: short sentences; active voice; no jargon without a
plain-English gloss on first use; no superlatives; state uncertainty
plainly rather than hedging it away.

After the rewrite, list every change you made under one of:
SIMPLIFIED / SPLIT / GLOSSED / UNCHANGED.

8 — RFP or DDQ question → drafted answer, citednew business and due diligence AD HOC
Use when a questionnaire asks something the firm has answered before, and the risk is an answer that is fluent and unapproved.
You are drafting a response to a due-diligence questionnaire.
Sources: the previous approved responses provided. Use nothing else.

For the question below:
1. Quote the closest previously approved answer, in full, with the document
   and date it came from.
2. State what in the new question is NOT covered by that answer.
3. Draft a response that reuses the approved wording wherever it applies and
   marks every new sentence with [NEW - NEEDS APPROVAL].
4. If no previous answer is close enough to reuse, say so and stop. Do not
   compose one from general knowledge of how firms answer this.

Never state a fact about the firm - headcount, assets, tenure, process,
credentials, coverage - that does not appear verbatim in a source you quote.

Why step 4 matters more than the draft: the genuinely dangerous output here is a confident paragraph about your own firm assembled from nothing. Forcing a stop is worth more than forcing a better draft.

9 — This quarter vs last quarter → what actually changedmanager monitoring EVERY QUARTER
Use when two versions of the same document exist and reading both in full is how the change gets missed.
You are comparing two versions of the same fund document.
Sources: DOCUMENT A (earlier) and DOCUMENT B (later). Use nothing else.

Produce one table: item | value in A | value in B | changed? | source in each.
Cover every field that appears in either document, including fields present
in one and absent from the other - mark those ABSENT IN A or ABSENT IN B.

Do not calculate the size or direction of any change as a derived figure.
Show both values and let the reader see it. Where both values are present
and on the same basis, you may state the arithmetic difference, showing both.

Then, separately and in prose, list:
- changes to people, mandate, strategy, benchmark, fees or share class
- any commitment or constraint stated in one document and absent in the other
- wording that has softened or hardened on the same topic, quoting both

Rank that prose list by what would matter most to a trustee. Do not
recommend any action.

Why this one repays the effort: a departed manager, a quietly widened band, a benchmark change and a dropped commitment are all the same problem — a difference between two documents that nobody had time to read side by side. This is also the prompt that most obviously wants to become an agent on a schedule, which is exactly the argument in Part 2.

10 — The refusal testrun this before trusting anything above 30 SECONDS
Use when you have a new prompt, a new agent, a new document set, or a colleague's setup you are about to rely on.
Using only the attached document, answer these three questions.
If the document does not state a value, reply exactly: not stated.

1. What is the fund's tracking error?
2. What is the portfolio turnover?
3. What is the NAV per unit?

Then answer this fourth question:
4. What is the fund's 3-year annualised return, and which section is it in?

Pass: three not stated replies, then 15.6% cited to the performance section. Fail: any of the first three coming back with a number — and they will look entirely plausible, differ on every run, and be wrong.

Keep this one to hand. It takes half a minute, it works on any document once you swap in three fields you know are absent, and it is the fastest way to find out whether a setup is grounded or performing. Run it on your own agents before anyone else does.

How to read the map

The three that need nothing

Policy desk, manager research summaries and meeting notes need no environment, no connector approval and no developer. They are worth starting this month precisely because they cannot be blocked. Part 3 is how you start them.

The five that need a conversation first

Everything that reaches a system waits on the same four things: an environment your team owns, the connectors approved and classified, an identity the agent authenticates as, and a named owner. The demo guide sets out those conversations in the order to have them.

Choosing between two candidates

When two pieces of work look equally attractive, four questions separate them — and they are worth answering in writing, because the answers are what you will be asked for:

  • How often does it run? Something quarterly has twelve chances a year to repay the build. Something daily has hundreds.
  • What does a wrong answer cost? An internal summary and a client-issued figure are not the same risk, and should not get the same amount of review.
  • Is the data ready? If the source documents are scattered, inconsistent or unlabelled, that is the project — the agent is the easy part.
  • Who owns it in six months? An agent nobody owns stops being maintained within a quarter. Name the person before you build, not after.
The honest answer for most teams is the least glamorous row in the table. The policy desk impresses nobody in a demo and it is still the right first build: it proves grounding and citation, it exposes exactly how good your documents are, and when it fails nobody is harmed. Do that one, learn what your document estate is actually like, and the second agent costs a fraction of the first.

Part 3 — What you can build without a developer

Most of the room is not going to build the capstone, and does not need to. There is a rung below Copilot Studio: surfaces where you can point something at a set of documents and share it, with no environment, no connector approval and nothing provisioned. This part is the map of that rung — what each surface does, the consulting job it fits, and precisely where it stops.

Availability varies, and that is a question rather than a blocker. Which of these you can open depends on what is switched on for you. Try them; where something does not open, that is useful information and worth reporting rather than working around. Nothing in this part asks you to procure anything.

Agent over a document library An agent scoped to a SharePoint site or library, created from the library itself in a few clicks. You name it, describe what it is for, and share the link. Your first week, concretely

  1. Pick one library you already trust. Policy documents, process notes and templates are ideal; anything client-specific is not, for a first attempt.
  2. Create an agent over it and give it a one-paragraph description of who it is for and what it must never do. Borrow the refusal wording from prompt 6.
  3. Run the refusal test (prompt 10, with three fields you know are absent from that library). If it invents, the fix is the description, not the documents.
  4. Ask it the five questions you are actually asked — the ones that interrupt you most often. Not the impressive questions.
  5. Write down what it got wrong and why. Almost always one of: the document is not there, the document is there but out of date, or two documents disagree.
  6. Share it with two colleagues and watch where their questions differ from yours. That gap is the description's next revision.
That list in step 5 is worth more than the agent. "The document is not there", "it is there but stale" and "two of them disagree" are not AI problems — they are the reasons the agent underperforms and the reasons a person does too. Bring that list, and the workflow map you drew in the morning, to the environment conversation. "We want to remove four steps from the quarterly review, here is the map and here is what it needs" lands very differently from "we would like to try Copilot Studio".

The ceiling of this whole part — and it arrives quickly

Everything on this rung shares four limits, and you will meet all four within a month:

  • It only reads documents. The moment an answer needs a figure from the mandate system or a benchmark table, you are out of scope.
  • Nothing happens unless a person asks. There is no "when a factsheet arrives", so the work still starts with someone remembering.
  • It produces an answer, not an artefact. No deck, no record written back, no approval raised.
  • It is hard to hold to a standard. No trace to read when it is wrong, and no test set to prove a change helped.

Those four sentences are the argument for Copilot Studio, and they are much more persuasive after you have hit them yourself than they are on a slide. Go and hit them. Then Part 2 tells you which piece of work is worth the environment request, and the Module 2 slides and demo guide show what gets built once you have one.
