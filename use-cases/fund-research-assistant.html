Fund Research Assistant

Build it yourself — Microsoft Copilot Studio
~90 minutes | Low code | 3 knowledge sources · 1 topic · 6 tools · 1 unattended flow | Trainer: Rajesh Gheware
Everything here is synthetic — keep it that way. The fund, the client and both workbooks are made up. By Stage 8 this agent writes files and sends mail on its own, so build it against your own test files, not a real factsheet or client reference.

What you are building

The agent the workshop demos build, in one sequence. It answers from fund documents and cites every figure, refuses to invent one, calls Excel and two systems for anything it may not work out itself, produces a validated slide plan — and by Stage 8 does all of that because a file arrived, with a human approving the result.

Each stage is usable on its own. Stop after 2 and you have a grounded research assistant; after 5, one that reaches your systems.

This page is the build sheet, and the only place the configuration is written down. Its companion is demo-guide.html, the run-sheet: what each demo proves, what to type, what you should see and what to do when it misbehaves. Demos 1.8 and 2.1–2.7 there each point back at the stage below that builds them. Nothing is duplicated between the two.

Stage 1 The agent, its rules, and closing the open web~12 min
  1. Create → New agent, then Skip to configure. Check the environment shown top-right is the one you meant.
  2. Name it Fund Research Assistant. Description: 
    Answers questions about fund factsheets for investment consultants. Quotes the source for every figure and refuses to estimate anything not in the document.
  3. Paste the Instructions: 
    You are a research assistant for an investment consulting team.

You answer questions about the fund documents in your knowledge only.

Rules you must follow without exception:
- Every figure you state must come from a document in your knowledge, or from
  an action you called. Never from your own knowledge of the world.
- After every figure, cite the section, page or action it came from.
- If a figure is not in your documents, reply exactly: not stated.
- Never estimate, infer or annualise a figure, and never fill a gap.
- Arithmetic: you may state the difference between two figures you have just
  retrieved, provided you show both of them with their sources in the same
  reply. Everything else that produces a number - totals, averages, weighted
  figures, currency conversion, anything computed across a set of rows - must
  come from an action. If no action provides it, name the action that is
  missing instead of working it out yourself.
- If asked for advice on whether to invest, decline and say that suitability
  is a consultant judgement, not a document lookup.
- Be brief. A consultant is reading this between meetings.

When asked to compare the fund against its benchmark, state both numbers and
the difference, and label the difference as excess return.
  4. Knowledge → Add knowledge → upload sample-fund-factsheet.pdf. Wait until its status says ready.
  5. Settings → Orchestration → confirm generative orchestration is on. Do this before testing. On the classic setting the agent only answers what a topic matches, and a research question matches none.
  6. Settings → Generative AI → switch both off:
    • Allow ungrounded responses — blocks any answer not built from knowledge or a tool. Stage 6 turns this one back on.
    • Use information from the Web.
  7. Only if it still cites a web page after that: Topics → System → Conversational boosting → off. Leave it alone otherwise — see troubleshooting.
  8. Test in the pane on the right, in a new conversation: 
    What is the fund's 3-year return versus its benchmark?
What is the tracking error?
Check
  • 15.6% fund, 13.1% benchmark, excess return 2.5%, cited to the performance section.
  • not stated for tracking error — the factsheet carries none.
  • Getting “I'm not sure how to help with that” instead? That is the stock Fallback topic, not a refusal. See the first troubleshooting row.
Stage 2 A second source, and one answer made non-negotiable~10 min
  1. Upload manager-update-jul-2026.txt as a second knowledge source.
  2. Click the source row to open its details page — give it a name, a one-line description, and mark it an official source. All three live there, not on an ellipsis menu.
    Marking it official also rewrites your agent's Instructions, adding a rule about preferring authoritative data. It does not show in the Instructions box.
  3. Ask a question neither document answers alone, then open the trace on the answer and read which source it used, in what order: 
    What did the manager say about the gold allocation, and does it match the allocation shown on the factsheet?
  4. Append the ambiguity rule to Instructions: 
    If a question is ambiguous about the period, the share class or the plan
(Regular or Direct), do not choose one silently. Ask which is meant, or state
every variant explicitly with its label.
  5. Topics → + Add a topic → From blank, named Advice refusal.
  6. There is no trigger-phrase list any more — a blank topic takes one free-text “Describe what the topic does” box, and the agent routes on it: 
    Fires when the user asks whether to invest in, buy, recommend or allocate to a fund, or whether one is suitable for a client - any question seeking an investment judgement rather than a document lookup. Example questions: Should my client invest in this fund? Is this a good fund? Would you recommend this fund? Is this fund suitable for our client? Do not use this topic for factual document lookups such as the recommended allocation stated in a mandate.
  7. Add a Message node with this wording, then Save: 
    I can't advise on whether to invest. Suitability depends on the client's
mandate, risk tolerance and existing allocation - that is a consultant
judgement, not a document lookup.

I can give you what the documents say: performance against the benchmark,
the allocation, the risk figures and the mandate limits. Ask me for any of
those and I will cite the source.
Check
  • The gold question answered from both documents, two citations.
  • Ask three ways — “should we buy this”, “is this a good fund”, “would you recommend it” — and get the same words every time. A sentence in Instructions is re-worded each run; a topic is not.
Stage 3 How a tool is built — read once, repeat five times~4 min

Every one of the six tools is the same four moves. Stages 4 to 7 only say what is different.

  1. make.powerautomate.com → Create → Instant cloud flow, trigger When an agent calls the flow. Name it.
  2. Add the trigger's inputs, do the work, finish with Respond to the agent carrying named outputs. Save, then test the flow on its own before attaching it.
    Each output takes an expression, entered with the fx button. Two rules cover every one below: a text output holding rows or a response body must be wrapped in string(…), because the connector hands you an array or an object and the output is typed text; a number output must be wrapped in float(…).
  3. In Copilot Studio: Tools → Add a tool → Workflows → pick your flow.
  4. Give the tool a description — this is how the agent decides to call it. Say when to use it, not just what it does.
Three traps that will cost you time.
  • The input names you type are display titles only. The body keys are generic — text, number, text_1. triggerBody()?['amountinr'] is always Null; insert values from the dynamic-content picker.
  • Publishing silently blanks number-typed outputs on Respond to the agent. Reopen and re-check after every publish.
  • Clicking the canvas + while a parameter panel is open sends your keystrokes into that panel's field.
Stage 4 Two tools that fetch — a public API and a legacy internal system~18 min
Tool 1 — Get FX Rate (premium: the HTTP action)
NodeConfigure
When an agent calls the flowTwo inputs: text ratedate, number amountinr.
HTTPMethod GET. The date in the path is the ratedate input — insert it from the dynamic-content picker. Use the .dev host and /v1/ path: the old .app host returns 301 and the action does not follow redirects. Hardcode the date and the tool advertises a ratedate it never uses. 
https://api.frankfurter.dev/v1/@{triggerBody()?['text']}?from=USD&to=INR
ComposeThe division, in the flow rather than in the model. 
div(
  triggerBody()?['number'],
  float(body('HTTP')?['rates']?['INR'])
)
Respond to the agenttext fxjson = string(body('HTTP'))
number amountusd = float(outputs('Compose'))

Test it alone (Test → Manually): ratedate = 2026-06-30, amountinr = 48200000000. Expect amountusd ≈ 509190788 at a rate of about 94.66. Run it again with 2026-03-31 and check the rate changes — that is how you know the input is wired.

Tool description:

Converts an amount in Indian rupees to US dollars at the exchange rate published
for a given date, and returns both the rate and the converted amount. Use this
whenever a value in rupees needs to be expressed in US dollars, or a currency
conversion is requested. Never convert currency yourself - always call this.
Input ratedate must be in YYYY-MM-DD format. Input amountinr is the rupee
amount as a plain number, so Rs 4,820 crore is passed as 48200000000.

Stage 6 Enforce a shape — the fund record and the slide plan~14 min
Turn Allow ungrounded responses back on first. With it off this stage does not run at all: bare JSON carries no citations, so the grounding gate suppresses the answer and you get “No information was found that could help answer this.”
  1. Append the extraction schema to Instructions: 
    When asked to extract a fund record, return valid JSON only - no commentary,
no markdown fence - with exactly these keys:

fund_name, isin, share_class, aum, currency, benchmark, manager,
inception_date, ter_regular, ter_direct, exit_load,
return_1y, return_3y, return_5y, return_since_inception,
benchmark_1y, benchmark_3y, benchmark_5y,
alloc_equity, alloc_debt, alloc_gold, alloc_cash,
as_of_date, source_document, needs_review

Rules:
- Every key must be present. Never add, remove or rename a key.
- If a value is absent from the document, use the string: not stated
- Percentages as strings with the percent sign, exactly as printed.
- as_of_date in YYYY-MM-DD.
- needs_review is a list of key names that were absent, ambiguous, or where the
  document gave more than one candidate value. Empty list if none.
- Never infer a value from another value, unless you also list that key in
  needs_review so the inference is visible to the next reader.
  2. Upload meridian-manager-update.txt as a third knowledge source, then run both commands and compare: 
    Extract the fund record from the Northwind factsheet.
Extract the fund record from the Meridian manager update document.
  3. Append the slide-plan schema. The plan is the interface — everything after it is ordinary code: 
    When asked to produce a fund review deck, output valid JSON only, with this shape:

{
  "deck_title": "",
  "client": "",
  "as_of": "YYYY-MM-DD",
  "slides": [
    {"layout":"title",   "title":"", "subtitle":""},
    {"layout":"kpi",     "title":"", "kpis":[{"label":"","value":"","source":""}]},
    {"layout":"table",   "title":"", "columns":[], "rows":[[]], "source":""},
    {"layout":"chart",   "title":"", "chart_type":"pie", "series":[{"label":"","value":0}], "source":""},
    {"layout":"comment", "title":"", "bullets":[""], "source":""}
  ],
  "unresolved": []
}

Rules:
- Every figure on every slide must carry a source string naming the document
  section or the action it came from.
- Any figure you could not source goes in unresolved, and does not appear on a slide.
- Never write a commentary sentence containing a number that is not on a slide.
- Five to seven slides. Commentary bullets: maximum twelve words each.
  4. Ask for the deck: 
    Produce a Q2 2026 fund review deck for client CL-4471 covering the Northwind
fund: performance against benchmark, asset allocation, top holdings, fees,
and a short commentary.
Check
  • Clean document: 25 keys, real values, needs_review close to empty. Verify every field against the factsheet by hand — this is the one place worth it.
  • Messy document: around eighteen or nineteen not stated, and needs_review naming the real ambiguities — the 11.4% return with no period, the “approximately” AUM, and as_of_date, which is never given.
  • Both parse. Paste one into a JSON validator.
  • Read the deck's commentary bullets against its slides. Expect a figure that is real, sourced, and on no slide — on a live run it cited a mandate ceiling of 70%. Tighten the rule and re-run.

Stage 7 Two tools that act — the gate, and the file~16 min
Tool 5 — Send Deck For Approval
NodeConfigure
When an agent calls the flowTwo inputs: text decksummary, text approver.
Create an approvalApprovals connector — not Start and wait for an approval, for the reason below. Type Basic, Assigned to = the approver input, Details = decksummary. First use asks you to create a connection; no credentials are typed.
Respond to the agenttext status = the literal words Pending approval — the one output here that is not an expression
text approvalid = outputs('Create_an_approval')?['body/name']

On the tool's Inputs in Copilot Studio, set approver to a Custom value holding a real address you can receive at. Left on Dynamically fill with AI, the agent invents an address and the approval goes nowhere.

Tool description:

Sends a finished client deck for human approval before it is issued. Must be used
before any output is described as final or client-ready. It returns as soon as the
request is sent, so the outcome is not known yet: report that approval is pending
and never describe the output as approved.
Why Create an approval and not Start and wait. A flow called by an agent has roughly 100 seconds to answer. Waiting on a human blows through it and the response leg fails with ActionResponseTimedOut or HTTP 504 — the approval succeeds, and the agent has already hung up. Stage 8 is allowed to wait, because a file starts that flow, not the agent.
Tool 6 — Build Review Deck
NodeConfigure
When an agent calls the flowOne input: text planjson.
HTTPMethod POST. URI https://<your-renderer-host>/api/render. Header Content-Type = application/json, plus your endpoint's auth — an Azure Function wants x-functions-key (see below). Body: 
@json(triggerBody()?['text'])
The json() is load-bearing: the plan arrives as a text input, so without it you post a quoted string where the endpoint expects an object.
Create fileOneDrive for Business. Content = body('HTTP'). Name timestamped, not fixed — a constant name overwrites yesterday's deck. 
concat('review-deck-', formatDateTime(utcNow(),'yyyyMMdd-HHmmss'), '.pptx')
Respond to the agenttext deckstatus = Deck saved to OneDrive as @{outputs('Create_file')?['body/Name']} — literal text with the expression inline, so the agent can name the file it wrote.

Tool description:

Turns a finished slide plan into a real PowerPoint file and saves it to OneDrive.
Use this after you have produced a fund review deck plan, when the user asks for
the deck to be built, generated or saved. Input planjson is the complete slide
plan as JSON text, exactly as you produced it.
What the endpoint has to do — the whole contract. Accept the slide plan as a JSON body, return the .pptx as raw bytes. No handshake, no callback, no polling. The next step writes the HTTP body straight to OneDrive, so whatever comes back is the file — if your renderer returns JSON saying “here is a link”, you will save that sentence as a .pptx.
Where the x-functions-key value comes from. Not typed into the header — the header holds an expression that reads an environment variable, so there is one place to rotate the key instead of a copy in every flow that calls the endpoint.
  1. Get the key: Azure portal → your Function App → App keys → the default host key. Or az functionapp keys list -g <rg> -n <app>.
  2. The flow must be inside a solution. A flow sitting in My flows cannot reference an environment variable at all. This is the step that is usually missed.
  3. Solutions → your solution → New → More → Environment variable. Data type Text. Put the key in Current Value.
  4. Reference it as the header value — display name, a space, then the schema name in brackets, exactly: @{parameters('Render endpoint key (new_RenderEndpointKey)')}. Get that name wrong and the header resolves to null and the endpoint returns 401.
  5. On the HTTP action, Settings → Secure Inputs. Without it the key is readable in every run's inputs in run history.
Know what this does not buy you. The designer stamps the variable's current value into the flow definition, so an exported solution still carries the key. It is one owned place to rotate — not a secret store. The real fix is a Secret environment variable backed by Azure Key Vault, resolved at run time and never written into the definition; it needs the vault in the same tenant and the Dataverse service principal granted get/list on secrets.
Simpler routes, honestly labelled: pasting the key literally works and is what most people do first — just remember there are two copies to rotate. Putting it on the query string as ?code=<key> is accepted by Functions but is worse, because the whole URL lands in run history.
No renderer endpoint? Build the flow as Create file writing plan.json instead, and do the last hop offline: python3 plan-to-pptx.py plan.json deck.pptx, or open deck-renderer.html in a browser and press Load plan.json. Same plan, and the agent cannot tell the difference. Test whichever route you use with the agent's own output, not a tidy fixture — a hosted renderer returned 500 on a deck title containing an em-dash while passing every local test.
Stage 8 Publish, then make it run without being asked~18 min
Part 1 — publish and share
  1. Publish. Nothing below works until it completes.
  2. Channels — behind the +2 overflow beside the tab strip, not on it. Teams and Microsoft 365 Copilot are now one tile, Microsoft 365 and Microsoft Teams. Turn it on and ask a question from inside Teams.
  3. Set the publisher name — Edit details → Teams settings → More (collapsed). Until you do it reads Your developer name.
  4. Share with one colleague. The choice is use versus co-author. Sharing an agent shares what it can do, not only what it knows — every tool runs under your credentials.
  5. Settings → Security → Authentication. With Authenticate with Microsoft on, knowledge results trim to each asker's own permissions. Off, everyone queries one index.
Part 2 — the trigger flow, Factsheet Arrived
  1. Create a library or folder called incoming-factsheets.
  2. New Automated cloud flow — not an instant one. Trigger: When a file is created (properties only), pointed at that folder.
  3. No Get file content step — the trigger already returns File content, File name and File path.
  4. Microsoft Copilot Studio → Execute Agent and wait (search the action list for copilot, not agent). Pick your agent, click Show all to reveal Message, and paste this with the trigger's File name token inside it: 
    A new fund document has arrived in the incoming-factsheets folder: [File name].
Extract the fund record using the schema in your instructions, enrich it with the
mandate and benchmark actions, and produce a slide plan for a quarterly review.
Produce the plan only: do not call the deck-building tool, because this process
renders the deck itself after a human has approved the plan.
Do not describe anything as final; the flow will send this for approval. Do not
state an approval id - you will not have one. If more than three fields are in
needs_review, do not produce a plan at all - report which fields failed and stop.
When you do produce a plan, end your reply with the slide plan as raw JSON
matching the slide-plan schema in your instructions, wrapped exactly in the
markers ===PLAN_JSON_START=== and ===PLAN_JSON_END=== with nothing after the
closing marker.
  5. Approvals → Start and wait for an approval — allowed here — assigned to yourself, Details = the agent's body/lastResponse. The flow creates the approval, not the agent: told to send one, the agent tends to narrate it instead of calling the tool, and no card appears.
  6. Condition — outcome equals Approve. Six actions in True, in order:
    • Compose — the plan, split out of the reply between the two markers: split(split(outputs('Execute_Agent_and_wait')?['body/lastResponse'],'===PLAN_JSON_START===')[1],'===PLAN_JSON_END===')[0]

    • Create file — the timestamped .pptx.
    • Convert file — PDF, File = the Id the previous step returned.
    • Create file — the .pdf.
    • Send an email (V2) — PDF attached.
  7. False branch: one Send an email (V2) saying the deck was rejected, no PDF was produced, nothing has gone to the client, and the reviewer's comment is in the run history.
  8. Append to Instructions: 
    When you are invoked by a process rather than by a person, nobody is present to
answer a follow-up question. So: never ask a clarifying question in that context.

and let the approval step put it in front of a human.
  9. Drop sample-fund-factsheet.pdf into the folder and close the tab. Come back in three to five minutes.
  10. Then drop the messy document in and watch what a triggered agent does when the document does not cooperate.
  11. Swap the trigger, change nothing else. Delete the trigger step and put Recurrence or When a new email arrives (V3) in its place. Everything downstream is untouched.
Check
  • Nothing, for several minutes — no window open, nobody waiting. Then an approval card carrying the fund record and slide plan.
  • Two entries in needs_review you did not plant: client_mandate (no client id was supplied, so the action was never called) and isin (the factsheet prints INF000SAMPLE01 (illustrative)). Two is under the threshold of three, so the plan is still produced.

Every tool runs as whoever built it — anyone you share with gets your Excel, OneDrive and mailbox reach. Decide whose credentials each tool uses, and turn on Settings → Security → Authentication.
